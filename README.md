## English

A lightweight CLI tool that fetches a URL's HTTP response headers and scores them against common web security best practices (similar in spirit to securityheaders.com, but self-hosted and offline-friendly).

### Overview

Missing or misconfigured HTTP security headers are a common, easy-to-fix source of risk: clickjacking, MIME-sniffing attacks, mixed-content downgrades, and overly permissive browser feature access. This tool checks a target URL for six widely recommended headers, explains what each one does, and produces a Markdown report with an overall grade.

### Installation

```bash
pip install -r requirements.txt
```

Or install as a CLI command:

```bash
pip install -e .
web-security-header-scanner --url https://example.com
```

Requires Python 3.9+ and the `requests` library — no other dependencies.

### Usage

```bash
python web_security_header_scanner.py --url https://example.com --output report.md
python web_security_header_scanner.py --url https://example.com --format json --output report.json
```

Options:

| Flag | Default | Description |
|---|---|---|
| `--url` | *(required)* | Target URL to scan |
| `--output` | `sample_report.md` | Path to write the report |
| `--timeout` | `5` | Request timeout in seconds |
| `--format` | `markdown` | Output format: `markdown` or `json` |
| `--fail-below` | *(none)* | Grade letter (`A`-`F`); exit code `1` if the actual grade is worse |

### What it checks

| Header | Why it matters |
|---|---|
| `Strict-Transport-Security` | Forces browsers to use HTTPS, preventing downgrade/SSL-stripping attacks |
| `Content-Security-Policy` | Restricts which script/style/frame sources the page may load, mitigating XSS |
| `X-Content-Type-Options` | `nosniff` stops browsers from MIME-sniffing away from the declared content type |
| `X-Frame-Options` | Prevents the page from being embedded in a hostile iframe (clickjacking) |
| `Referrer-Policy` | Limits how much referrer information leaks to other origins |
| `Permissions-Policy` | Disables unneeded browser features (camera, microphone, geolocation, ...) |

Score is `<headers correctly configured> / 6`, mapped to a letter grade (6=A, 5=B, 4=C, 3=D, 2=E, 0-1=F).

### Example Output

See [`sample_report.md`](./sample_report.md), generated by running the tool against `https://github.com`.

### CI Integration

`--fail-below` gates a pipeline on the resulting grade — useful as a regression check so a future deploy can't silently drop a security header:

```bash
web-security-header-scanner --url https://example.com --fail-below B
```

```yaml
# GitHub Actions step
- name: Enforce minimum security header grade
  run: web-security-header-scanner --url https://example.com --fail-below B
```

A failed HTTP request also exits `1` regardless of `--fail-below`. Omit the flag for a plain report with no CI gating.

### Testing

The header-evaluation logic is pure (no network calls), so the test suite runs fully offline:

```bash
pip install -r requirements-dev.txt
pytest -v
ruff check .
```

## Türkçe

Bir URL'nin HTTP yanıt header'larını çeken ve bunları yaygın web güvenliği en iyi uygulamalarına göre puanlayan hafif bir CLI aracı (ruhen securityheaders.com'a benzer, ancak self-hosted ve offline kullanıma uygun).

### Genel Bakış

Eksik veya yanlış yapılandırılmış HTTP güvenlik header'ları, yaygın ve düzeltmesi kolay bir risk kaynağıdır: clickjacking, MIME-sniffing saldırıları, mixed-content düşürmeleri (downgrade) ve aşırı izinli tarayıcı özellik erişimi. Bu araç, hedef bir URL'yi yaygın olarak önerilen altı header için kontrol eder, her birinin ne işe yaradığını açıklar ve genel bir notla birlikte bir Markdown raporu üretir.

### Kurulum

```bash
pip install -r requirements.txt
```

Veya bir CLI komutu olarak kurun:

```bash
pip install -e .
web-security-header-scanner --url https://example.com
```

Python 3.9+ ve `requests` kütüphanesini gerektirir — başka bağımlılık yoktur.

### Kullanım

```bash
python web_security_header_scanner.py --url https://example.com --output report.md
python web_security_header_scanner.py --url https://example.com --format json --output report.json
```

Seçenekler:

| Bayrak (Flag) | Varsayılan | Açıklama |
|---|---|---|
| `--url` | *(zorunlu)* | Taranacak hedef URL |
| `--output` | `sample_report.md` | Raporun yazılacağı dosya yolu |
| `--timeout` | `5` | Saniye cinsinden istek zaman aşımı |
| `--format` | `markdown` | Çıktı formatı: `markdown` veya `json` |
| `--fail-below` | *(yok)* | Not harfi (`A`-`F`); gerçek not daha kötüyse çıkış kodu `1` olur |

### Neyi Kontrol Eder

| Header | Neden Önemli |
|---|---|
| `Strict-Transport-Security` | Tarayıcıları HTTPS kullanmaya zorlayarak downgrade/SSL-stripping saldırılarını önler |
| `Content-Security-Policy` | Sayfanın hangi script/style/frame kaynaklarını yükleyebileceğini kısıtlayarak XSS'i azaltır |
| `X-Content-Type-Options` | `nosniff`, tarayıcıların beyan edilen içerik türünden MIME-sniffing yapmasını durdurur |
| `X-Frame-Options` | Sayfanın kötü niyetli bir iframe içine gömülmesini engeller (clickjacking) |
| `Referrer-Policy` | Ne kadar referrer bilgisinin diğer origin'lere sızacağını sınırlar |
| `Permissions-Policy` | Gereksiz tarayıcı özelliklerini devre dışı bırakır (kamera, mikrofon, konum, ...) |

Puan `<doğru yapılandırılmış header sayısı> / 6` şeklindedir ve bir harf notuna eşlenir (6=A, 5=B, 4=C, 3=D, 2=E, 0-1=F).

### CI Entegrasyonu

`--fail-below`, bir pipeline'ı sonuçtaki nota göre kapı (gate) haline getirir — ileride yapılacak bir deploy'un bir güvenlik header'ını sessizce düşürememesini sağlayan bir regresyon kontrolü olarak faydalıdır:

```bash
web-security-header-scanner --url https://example.com --fail-below B
```

```yaml
# GitHub Actions step
- name: Enforce minimum security header grade
  run: web-security-header-scanner --url https://example.com --fail-below B
```

Başarısız bir HTTP isteği de, `--fail-below`'dan bağımsız olarak `1` ile çıkış yapar. CI kapısı olmadan sade bir rapor için bayrağı atlayın.
